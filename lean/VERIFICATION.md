# Lean verification of online maximin share allocation with known types

Release `lean-v1.0.1` accompanies *An Order-Optimal Square-Root Bound for Online Maximin Share Allocation with Known Types*, by Zheyu Zhou. The declarations below use the numbering of the November 21, 2026 manuscript. Lean is pinned to `leanprover/lean4:v4.19.0`. The Mathlib revision and all transitive package revisions are fixed in [lake-manifest.json](lake-manifest.json).

## Reproduce

From the directory containing `lean-toolchain` and `lakefile.toml`, run the following commands with Lean's `elan` installation available. The first command obtains the pinned dependencies' compiled cache. The second compiles the project's proofs. The third prints the statements and transitive axioms of the audited declarations.

```sh
lake exe cache get
lake build
lake env lean Audit.lean
```

## Model and assumptions

- The instance and the positive number of arrivals are known before the first decision. The item set can be empty. Each of the positive number of types has a nonnegative additive valuation with real singleton values. Types can coincide, repeat, or never occur. The quantified arrival sequences range over every map from `Fin n` to `Fin k`. The bit-complexity results use explicitly listed rational singleton values. On an empty item set the implemented policies return an empty bundle immediately, even when the number of types has a short binary encoding but is very large. [Model](OnlineMMS/Model.lean) · [Benchmarks](OnlineMMS/Benchmarks.lean)
- Every deterministic policy is equivalent to maps indexed by the revealed prefix. A legal play gives disjoint bundles covering the original goods. Early choices are irrevocable and the last arrival receives the remainder. Completing a legal partial allocation this way preserves every successful payment. For a legal policy, all the payoff inequalities on a fixed sequence are equivalent to the capped manuscript score with the original benchmarks. When every revealed benchmark is zero, the score is one. [Prefix rules and score](OnlineMMS/PolicyPaths.lean) · [Feasibility](OnlineMMS/ManuscriptModel.lean)
- A fixed instance admits one lottery over deterministic policies. For each fixed sequence its success event requires every agent to meet the threshold. The lottery may have arbitrary real masses. Measurable random tapes on any probability space, with almost-sure feasibility, induce the same finite distribution over policies. An adaptive opponent has access to the preceding allocations. [Fixed-sequence benchmark](OnlineMMS/RandomBenchmark.lean) · [Random tapes](OnlineMMS/TapeLottery.lean) · [Adaptive arrivals](OnlineMMS/AdaptiveArrivals.lean)

## Proof of the randomized lower bound

The manuscript and Lean prove the positive-failure lower bound of Proposition 2.3 using the same policy. For an integer h ≥ 16, independently drawing one good uniformly from each full bucket gives every agent at least 1/(8h) of MMS simultaneously with probability at least 1 − 15/h² on each fixed sequence. For 0 < δ < 1, choosing h = ⌈16/√δ⌉ gives a fraction of at least √δ/136. The upper proof averages failures over all pair supports to choose a single fixed second type. [Construction](OnlineMMS/ObliviousLower.lean) · [Failure estimate](OnlineMMS/ObliviousTail.lean) · [Pair averaging](OnlineMMS/ObliviousPairCounting.lean)

For a fixed sequence, follow the potential of the type due at a particular later arrival. Write \(r\) for the remaining agents, \(s\) for prior samples and \(D=r+s-w_t(R)\) for that type’s deficit. Before any sample its normalized potential is one. The single-bucket means imply that one independent sample increases the expected exponential of the deficit by a factor at most three. Thus \(h^D/3^s\) has expectation at most one throughout the process. When \(r\ge2\), remaining weight at least \((r+s)/4\) suffices to pay the agent. A failed payment after sampling therefore uses at most a probability charge of \((3/h^2)2^{-(r-2)}\). The last agent contributes at most \(9/h^2\). Summing these bounds gives \(15/h^2\) over the entire fixed sequence. [One-step proof](OnlineMMS/ObliviousLowerSteps.lean) · [Summing over arrivals](OnlineMMS/ObliviousTail.lean)

## Reproducibility and trust

The audit follows the proof dependencies of every project theorem, including private lemmas, and accepts only Lean's three standard axioms `propext`, `Classical.choice` and `Quot.sound`. It also prints individual dependency lists for the principal declarations. [Audit](Audit.lean)

The kernel verifies all three finite computations. For Lemma 4.3 it counts 7,581 antichains by branching on whether to include each five-bit pattern. A proof identifies this count with the complete, duplicate-free catalogue. For each antichain the kernel checks that a proposed half-selection has the required size and satisfies all five coordinate bounds. For Corollary C.2 it checks the integer comparisons for 0 ≤ k ≤ 1,680 using a bounded binary search whose result is proved equal to the required ceiling. An analytic argument covers every larger k. [Antichain count](OnlineMMS/AntichainCount.lean) · [Balanced selections](OnlineMMS/BinaryPatterns.lean) · [Finite envelope](OnlineMMS/FiniteEnvelope.lean)

The cost results count rational operations, comparisons and array accesses for the specified algorithms and bound the sizes of rational operands. The abstraction treats rational arithmetic and comparisons as counted operations with explicitly bounded operands. Compiler code generation and physical execution time are outside this model. Section 6 states open questions.
